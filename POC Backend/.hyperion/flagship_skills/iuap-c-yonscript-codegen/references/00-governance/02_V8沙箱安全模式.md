## 核心原则

YonScript 运行在 V8  引擎的沙箱环境中，具有以下特性：

1. **沙箱执行模型**：`this` 的绑定在编译期和运行期可能不一致
2. **严格模式**：部分 ES6+ 特性不可用或行为不一致
3. **安全性**：禁止访问沙箱外部的方法和属性

**核心原则**：
- ✅ 使用 `function` 定义函数
- ✅ 变量声明允许 `var`/`let`，优先遵循平台模板和项目风格
- ✅ 平台模板壳首行必须原样保持 `let AbstractTrigger = require('AbstractTrigger');` 或 `let AbstractAPIHandler = require('AbstractAPIHandler');`，其前后不可新增空格、空行、注释或换行
- ✅ `this` 在类内方法调用场景可用；如运行环境验证不稳定，再退回闭包函数方案
- ✅ 必须 `return {}` 和 `exports`
- ✅ 修改既有脚本时必须保持补丁边界前后三行原样，不在边界行增删注释、改格式或顺手重排；必要注释只能写入本次被修改逻辑内部

## 函数定义规范

### 必须使用 function 定义

```javascript
// ✅ 正确：使用 function 定义
function queryData() {
    return ObjectStore.queryByYonQL(sql, domain);
}

// ✅ 正确：函数表达式必须配合 var
var queryData = function() {
    return ObjectStore.queryByYonQL(sql, domain);
};

// ❌ 错误：使用箭头函数
const queryData = () => {
    return ObjectStore.queryByYonQL(sql, domain);
};

// ❌ 错误：使用 const 定义函数
const queryData = function() {
    return ObjectStore.queryByYonQL(sql, domain);
};
```

### 函数参数

```javascript
// ✅ 正确：普通参数
function queryData(sql, domain) {
    return ObjectStore.queryByYonQL(sql, domain);
}

// ✅ 正确：默认参数（V8支持）
function queryData(sql, domain) {
    domain = domain || 'defaultDomain';
    return ObjectStore.queryByYonQL(sql, domain);
}

// ❌ 错误：解构参数（部分V8版本不支持）
function queryData({ sql, domain }) {
    return ObjectStore.queryByYonQL(sql, domain);
}
```

## 变量声明规范

### 变量声明使用 var 或 let

```javascript
// ✅ 正确：使用 var
var sql = "select id, code from aa.vendor.Vendor";
var result = ObjectStore.queryByYonQL(sql, 'yssupplier');

// ✅ 正确：平台模板或局部变量可使用 let
let sql = "select id, code from aa.vendor.Vendor";
let result = ObjectStore.queryByYonQL(sql, 'yssupplier');

// ⚠️ 谨慎：const 仅在目标平台已验证支持时使用
const sql = "select id, code from aa.vendor.Vendor";
const result = ObjectStore.queryByYonQL(sql, 'yssupplier');
```

### 变量命名

```javascript
// ✅ 正确：驼峰命名
var billId = '1234567890';
var mainData = {};
var detailList = [];

// ❌ 错误：下划线命名
var bill_id = '1234567890';
var main_data = {};

// ❌ 错误：匈牙利命名
var strBillId = '1234567890';
var arrDetailList = [];
```

## this 引用规范

### 强约束：类内方法调用必须带 this

> ⚠️ **强制规则**：所有类内方法调用**必须**使用 `this.方法名()`，禁止在类体内直接裸调方法名。

```javascript
// ✅ 正确：类内方法调用带 this
class MyTrigger extends AbstractTrigger {
    execute(context, param) {
        var result = this.queryData(sql, domain);
        return {};
    }
    queryData(sql, domain) {
        return ObjectStore.queryByYonQL(sql, domain);
    }
}
```

```javascript
// ❌ 错误：类内方法调用不带 this
class MyTrigger extends AbstractTrigger {
    execute(context, param) {
        var result = queryData(sql, domain);  // ❌ 缺少 this
        return {};
    }
    queryData(sql, domain) {
        return ObjectStore.queryByYonQL(sql, domain);
    }
}
```

### 原因说明

1. **编译期**：`this` 指向类实例
2. **运行期**：带 `this.` 可保证方法绑定到当前实例，不依赖作用域查找
3. **可维护性**：`this.xxx()` 便于在 BIP 后端函数设计器中分段定位

### 结构组织原则

- 可复用函数**必须**定义为类内方法，通过 `this.xxx()` 调用。
- 不再推荐在 `execute` 内部定义局部 function 再裸调的方式。
- 若确有需要，局部函数只做纯计算，不调用类内方法。

## 类定义规范

### 类名固定

```javascript
// ✅ 正确：Rule 脚本使用 MyTrigger
var AbstractTrigger = require('AbstractTrigger');
class MyTrigger extends AbstractTrigger {
    execute(context, param) {
        // 业务逻辑
        return {};
    }
}
exports({ entryPoint: MyTrigger });

// ✅ 正确：API 脚本使用 MyAPIHandler
var AbstractAPIHandler = require('AbstractAPIHandler');
class MyAPIHandler extends AbstractAPIHandler {
    execute(request) {
        // 业务逻辑
        return {};
    }
}
exports({ entryPoint: MyAPIHandler });
```

### 禁止修改类名

```javascript
// ❌ 错误：修改类名
class QueryCustomerHandler extends AbstractAPIHandler {  // ❌ 错误
    execute(request) {
        return {};
    }
}
exports({ entryPoint: QueryCustomerHandler });  // ❌ 错误
```

## 模块导出规范

### 必须 exports

```javascript
// ✅ 正确：必须 exports
exports({ entryPoint: MyTrigger });

// ❌ 错误：省略 exports
// （脚本无法被调用）
```

### 必须 return {}

```javascript
// ✅ 正确：必须 return {}
class MyTrigger extends AbstractTrigger {
    execute(context, param) {
        // 业务逻辑
        return {};  // ✅ 正确
    }
}

// ❌ 错误：省略 return {}
class MyTrigger extends AbstractTrigger {
    execute(context, param) {
        // 业务逻辑
        // 缺少 return {}  // ❌ 错误
    }
}
```

## 闭包模块化模式

### 推荐模式

```javascript
// ============================================
// 闭包模块化模式（推荐）
// ============================================

var MyModule = (function() {
    // 私有变量
    var privateVar = 'private';

    // 私有函数
    function privateFunc() {
        return privateVar;
    }

    // 公开接口
    return {
        publicMethod: function() {
            return privateFunc();
        }
    };
})();

// 使用
var result = MyModule.publicMethod();
```

### 在 YonScript 中的应用

```javascript
var AbstractTrigger = require('AbstractTrigger');

class MyTrigger extends AbstractTrigger {
    execute(context, param) {
        var billId = param.data[0].id;
        var result = this.queryMainTable(billId);
        return {};
    }
    queryMainTable(billId) {
        var sql = "select id, code from xxx.yyy.EntityVO where id = '" + billId + "'";
        console.error('【MyTrigger】查询SQL:' + sql);
        return ObjectStore.queryByYonQL(sql, 'xxx');
    }
}
exports({ entryPoint: MyTrigger });
```

## 常见错误示例

### 错误1：使用箭头函数

```javascript
// ❌ 错误
const queryData = () => {
    return ObjectStore.queryByYonQL(sql, domain);
};

// ✅ 正确
function queryData() {
    return ObjectStore.queryByYonQL(sql, domain);
}
```

### 错误2：使用 let/const

```javascript
// ❌ 错误
var sql = "select id from aa.vendor.Vendor";
const domain = 'yssupplier';

// ✅ 正确
var sql = "select id from aa.vendor.Vendor";
var domain = 'yssupplier';
```

### 错误3：在非类内场景滥用 this

```javascript
// ❌ 错误：把自由函数挂到 this 上
this.queryData = function() { ... };
var result = this.queryData();

// ✅ 正确：类内方法调用
class MyTrigger extends AbstractTrigger {
    execute(context, param) {
        var result = this.queryData();
        return {};
    }
    queryData() {
        return [];
    }
}
```

### 错误4：省略 return {}

```javascript
// ❌ 错误
class MyTrigger extends AbstractTrigger {
    execute(context, param) {
        // 业务逻辑
        // 缺少 return {}
    }
}

// ✅ 正确
class MyTrigger extends AbstractTrigger {
    execute(context, param) {
        // 业务逻辑
        return {};
    }
}
```

### 错误5：省略 exports

```javascript
// ❌ 错误
class MyTrigger extends AbstractTrigger {
    execute(context, param) {
        return {};
    }
}
// 缺少 exports({ entryPoint: MyTrigger });

// ✅ 正确
class MyTrigger extends AbstractTrigger {
    execute(context, param) {
        return {};
    }
}
exports({ entryPoint: MyTrigger });
```

## 检查清单

生成代码后，必须逐项检查：

| # | 检查项 | 规范 | 检查 |
|---|--------|------|------|
| 1 | 函数定义 | 使用 `function`，禁止箭头函数 | ☐ |
| 2 | 变量声明 | 允许 `var`/`let`，优先遵循平台模板和项目风格；`const` 需平台验证 | ☐ |
| 3 | this 引用 | 类内方法调用**必须**带 `this.`，禁止裸调 | ☐ |
| 4 | 类名 | 固定 `MyTrigger`/`MyAPIHandler` | ☐ |
| 5 | return | 必须 `return {}` | ☐ |
| 6 | exports | 必须 `exports({ entryPoint: ... })` | ☐ |
| 7 | 结构组织 | 优先类内方法，必要时再退回闭包模块化 | ☐ |
