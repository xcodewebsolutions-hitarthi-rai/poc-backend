# YonSQL 信息充分性门禁

> **加载时机**：当需求涉及 YonSQL 拼装、业务对象查询、参照字段过滤、结果回写时。
> **说明**：平台执行方法名仍为 `ObjectStore.queryByYonQL`。
> **职责**：先判断 YonSQL 所需信息是否充分，再决定是否调用 `iuap-c-metadata-info`。
> **与 08_生成准确性保障.md 的关系**：本门禁判断"要不要查"；08 门禁管"查不了时怎么保证可校验"。

---

## 1. 核心原则

公有云项目中，YonSQL 采用"**信息充分优先，缺口补采集**"原则：

- 若需求已明确给出 `uri`、`domain`、字段、查询条件，且四者可回溯到需求原文，可直接拼装。
- 只要四要素任一不明确，或参照链不完整，必须先调用 `iuap-c-metadata-info`。
- **直拼不等于臆想**：即使四要素看起来都"知道"，也必须走 Evidence Gate 标注可信度。
- YonSQL 默认不以 `cast(...)` 作为通用方案，Long 风险优先在结果侧处理。

### 1.1 关键修正：主观判断 → 客观可追溯

> ⚠️ **模型不能自评"我觉得我知道"就跳过元数据查询。**

"充分"的判定标准不是模型的主观信心，而是**客观可追溯**：

| 来源 | 是否算"充分" |
|---|---|
| 用户在需求中明确写了 URI、domain、字段 | ✅ 充分 |
| 本轮实际调了元数据脚本拿到了结果 | ✅ 充分 |
| 模型凭经验/训练数据"知道" | ❌ **不算充分**，必须标注 🟡 待确认 |
| 从文档/方案中查到的记录 | 🟡 可用但必须标注待确认 |

## 2. 四要素判定

### 2.1 可直接拼装（🟢 已确认）

满足以下**全部**条件时，可标 🟢 直接拼装：

1. `uri` 由用户在需求中明确给出，或本轮元数据查询确认。
2. `domain` 由用户明确给出，或本轮元数据查询 `_entityInfo.domain` 确认。
3. 字段来自用户明确给出的字段名，或本轮元数据查询 `attributes[].name` 确认。
4. 查询条件已明确到字段和值。

### 2.2 可拼装但需标注（🟡 待确认）

以下情况可以拼装，但**必须标 🟡 并在代码中加 ⚠️ 注释**：

- URI/domain/字段来自仓库内的方案文档，未经本轮元数据验证。
- URI/domain/字段来自模型经验/模式匹配，未经用户确认。
- 元数据查询环境不可用，无法实际验证。

### 2.3 必须补采集

只要出现以下任一情况，且元数据查询环境**可用**，必须补查：

- `uri` 不明确。
- `domain` 不明确。
- 字段语义明确但字段名不明确。
- 查询条件只给业务语义，未给落字段。
- 涉及参照字段，但 `refUri` 或目标字段不明确。
- 涉及特征组，但特征字段编码不明确。
- 涉及子表嵌套查询，但子表运行时关联字段不明确。
- 涉及多选引用，但多选引用运行时关联字段或实际存储字段不明确。
- 涉及特征字段，但特征组字段、特征编码、特征类型或多选档案引用结构任一不明确。
- 涉及平行表字段，但平行表 URI/domain/关联键任一不明确。
- 涉及业务外键关联，但源实体或目标实体 domain 未通过元数据确认。
- 元数据已返回但字段类型未确认，或无法判断基本类型/参照/特征/子表/平行表/多选引用/业务外键关联。

> 如果元数据查询环境**不可用**，回到 2.2，标 🟡 待确认，并在代码中加 ⚠️ 注释。

---

## 3. 参照递归规则

如果 YonSQL 涉及参照字段：

- 先判定主对象四要素是否充分。
- 若参照链完整（用户给出或元数据确认），可直接拼装。
- 若参照链不完整：
  - 环境可用 → 先查主元数据，再查 `refUri` 对应元数据。
  - 环境不可用 → 标 🟡 待确认，加 ⚠️ 注释。

---

## 4. 嵌套查询与特征字段门禁

### 4.1 参照穿透

生成参照嵌套查询前，必须确认：

- 外层参照字段名来自主实体元数据。
- 内层目标字段来自参照实体元数据，禁止臆想 `code/name`。
- 外层 `select` 必须显式包含该参照字段。

### 4.2 主子表嵌套

生成主表查子表嵌套查询前，必须确认：

- 主实体 `id` 被外层返回。
- 子表运行时关联字段来自元数据或平台公式元数据。
- 子表字段来自子实体元数据。
- 外层不得直接选择组合子表关联字段。

### 4.3 多选引用

生成多选引用查询前，必须确认：

- 外层主实体 `id` 被返回。
- 多选引用的运行时关联字段已确认。
- 多选引用表内实际存储档案的字段已确认。
- 若需返回档案 `id/code/name`，必须确认档案 `refUri` 与目标字段。

### 4.4 特征字段

生成特征字段查询前，必须确认：

- 特征组字段名，例如 `productCharacterDef`、`merchantCharacter`。
- 特征编码是否位于特征组内部，禁止默认按主表直属字段查询。
- 特征类型：文本/布尔/数值/单选档案/多选档案。
- 多选档案特征必须同时携带原特征字段，并用嵌套查询返回档案详情。

### 4.5 平行表

生成平行表取数前，必须确认：

- 平行表是独立业务对象，不是主表字段或子表 key。
- 平行表 URI/domain 已确认。
- 主表与平行表的关联键已确认。
- 默认分步查询并在脚本中合并，不默认生成 JOIN。

### 4.6 业务外键关联

生成业务外键关联查询前，必须确认：

- 该字段只是业务外键 ID，不存在 `refUri`、原生主子关系或特征关系。
- 源实体 URI/domain 已由元数据确认。
- 目标实体 URI/domain 已由元数据确认。
- 自动比较源实体和目标实体的 `_entityInfo.domain`。
- domain 相同才允许 LEFT JOIN；domain 不同必须分域查询并脚本组装。
- 禁止凭 URI 前缀、字段名、单据名称判断是否跨域。

---

## 5. 决策流程

```text
需求拆解
  → 判断 YonSQL 四要素是否充分
  │
  ├─ 充分且来源是用户/元数据查询 → 🟢 直接拼装
  │
  ├─ 来源是文档/经验 → 🟡 可拼装，但加 ⚠️ 注释
  │
  └─ 不充分
      ├─ 元数据环境可用 → 调 iuap-c-metadata-info 补齐
      └─ 元数据环境不可用 → 🟡 标待确认，加 ⚠️ 注释
  → 输出证据表（见 08_生成准确性保障.md）
  → 确认字段类型并选择写法
  → 拼装 YonSQL
```

---

## 6. 输出要求

生成结果里必须输出证据表（详见 `08_生成准确性保障.md`）：

- 每个 URI/domain/字段标注可信度（🟢/🟡/🔴）。
- 每个 🟡 项标注来源和待确认原因。
- 代码中每个 🟡 项必须有 ⚠️ 注释块。
