# 自动事实漂移检测与事实锁定门禁

> **加载时机**：生成前发现最新提示词中的业务对象、页面、子表、字段、项目名、URI/domain 与本 session 已有事实或历史实现不一致，或准备复用旧代码/旧文件/旧元数据前必须加载。
> **职责**：由 agent 主动检测事实漂移，自动重建当前事实锁，隔离历史噪音；用户显式纠偏只是触发信号之一，不是必要条件。

---

## 1. 第一原则

agent 必须自己判断当前提示是否引入了新的业务事实，不能把识别责任转嫁给用户。

最新提示词抽取出的高权重业务事实，高于同 session 历史上下文、高于已有代码、高于模型记忆、高于文件命名相似度。

用户显式说“不是 X，是 Y”只是事实漂移的一种强信号；即使用户没有显式否定旧对象，只要最新提示出现新的业务对象、页签、子表或领域词，与上一轮实现对象不一致，也必须自动进入本门禁。

## 2. 自动检测流程

生成前必须按以下顺序执行轻量检测；只有检测到漂移风险时才展开本门禁细节：

1. 从最新提示词抽取高权重业务事实。
2. 从当前 session 历史实现中抽取已使用事实。
3. 对比最新事实与历史事实。
4. 若业务对象、子表、字段组、URI/domain、项目名任一不一致，则判定为事实漂移。
5. 事实漂移后，自动重建当前事实锁，并把旧事实列为排除对象。

## 3. 高权重事实

以下事实必须由 agent 主动抽取和对比：

| 类型 | 示例 | 漂移后的动作 |
|---|---|---|
| 业务对象/单据 | 采购结果、定标单、定标变更 | 重新查当前对象元数据 |
| 页面/页签/子表 | 调整定标明细、中标物料明细 | 重新确认子表字段和实体 |
| 字段组/特征组 | `dsnMaterialDetailDefineCharacter` | 禁止沿用旧特征组 |
| URI/domain | `lawbid.decisionresult.CpuDecision` | 旧 URI/domain 全部作废 |
| 项目/客户 | 普莱克、其他客户名 | 重新隔离项目专用实现 |
| 交付意图 | 重新生成一份、本需求、这个功能 | 新建干净交付，非旧代码 patch |

## 4. 触发信号

命中任一信号时必须执行事实锁定：

- 同一 session 内出现 2 个及以上候选业务对象，例如定标单、定标变更、采购结果。
- 当前提示词中的业务对象/子表/领域词与上一轮实现对象不一致。
- 当前提示词出现新的高权重业务名词，例如“采购结果”“调整定标明细”“付款单”“采购合同”，且历史代码/文件名仍指向旧对象。
- 用户明确纠偏业务对象、页面、子表、字段或项目归属。
- 准备从已有代码中复制、改名、迁移逻辑。
- 元数据查询结果与历史文件命名或旧实现不一致。
- 生成前发现当前事实依赖来自多轮不同提示。

## 5. 事实锁定表

生成任何代码前必须先在内部锁定以下事实；缺失则补查元数据或询问用户，不能用旧上下文填空：

| 项 | 要求 |
|---|---|
| 当前业务对象 | 以最近明确提示为准，例如“采购结果” |
| 当前页面/子表 | 以最近明确提示 + 元数据确认，例如 `materialList` |
| 主实体 URI/domain | 必须来自当前业务对象元数据 |
| 子实体 URI/domain | 必须来自当前业务对象元数据 |
| 字段映射 | 供应商、组织、物料、目标字段、校验字段逐项确认 |
| 排除对象 | 列出本轮废弃的历史对象，例如定标单、定标变更 |
| 禁止关键词 | 由排除对象生成，例如 `pricedecision`、`pdrevise`、旧特征组名 |

## 6. 历史噪音隔离规则

- 历史代码只能作为“实现模式参考”，不能作为业务事实来源。
- 用户纠偏后，旧文件默认作废；除非用户明确要求“在旧文件上改”，否则应新建干净交付。
- 隐式语义冲突与显式纠偏同等处理；即使用户没有直接否定旧对象，只要最新提示已给出新对象，就必须重置事实。
- 先查当前业务对象元数据，再看历史代码；禁止先搜索旧代码并让旧代码反向决定实体和字段。
- 如果旧代码和当前元数据冲突，以当前元数据为准；若元数据缺字段，标注待确认，不得拿旧字段补齐。

## 7. 生成前排除检查

生成前必须检查候选代码是否包含排除对象的 URI、字段组、函数名或文件名前缀。

示例：当前锁定为“采购结果”时，如果排除对象包含“定标变更/定标单”，则生成物不得出现：

- `sourcing.pricedecision`
- `sourcing.cpupdrevise`
- `PriceDecisionDetailDefineCharacter`
- `cpuPdreviseDetailDefineCharacter`
- 与当前元数据无关的 `bodys`

命中禁止关键词时，生成失败，必须回到事实锁定表重新生成。

## 8. 输出要求

交付说明中必须列出当前事实来源，至少包含：

- 当前业务对象。
- 当前子表字段。
- 主/子实体 URI 与 domain。
- 字段映射。
- 已排除的历史对象或旧实现。

## 9. 渐进式加载约束

主入口只执行轻量事实漂移检测；仅在检测到多对象、漂移、复用旧代码等风险时加载本文档完整规则。普通单轮、单业务对象、无历史冲突的生成任务不展开本文档细节。
