# 协同能力信息充分性门禁

> **加载时机**：当需求涉及 OpenAPI、事件、MDF 前端协同时。
> **职责**：统一判定 OpenAPI / 事件 / MDF 是否可直接生成，还是必须先调协同 skill 补信息。

---

## 1. 核心原则

公有云项目中，协同能力也遵循“**信息充分优先，缺口补采集**”原则：

- 信息已充分且可追溯时，可直接进入生成。
- 任一关键要素不明确时，必须先调对应 skill 补齐。
- 协同 skill 只负责查信息或生成前端，不接管公有云后端主编排。

---

## 2. OpenAPI 判定

### 2.1 可直接进入生成

以下信息都已明确时，可直接生成调用代码：

1. URL
2. method
3. request 结构
4. response 结构

### 2.2 必须补采集

任一项不明确时，必须先调 `iuap-c-openapi-integration`：

- URL 不明确
- method 不明确
- request 字段不明确
- response 结构不明确

---

## 3. 事件判定

### 3.1 可直接进入生成

以下信息都已明确时，可直接生成事件逻辑：

1. eventCode
2. 事件报文结构
3. 事件订阅 API 地址
4. method / request / response

### 3.2 必须补采集

任一项不明确时，必须先调 `iuap-c-event-integration`。

---

## 4. MDF 判定

### 4.1 可直接进入生成

以下信息都已明确时，可直接协同前端生成：

1. 页面实体和字段来源
2. 前后端交互方式
3. 按钮/事件挂载点
4. 依赖的后端接口或字段

### 4.2 必须补采集

任一项不明确时，必须先补元数据，必要时再调 `iuap-c-mdf-codegen`。

### 4.3 MDF 调后端 API 的附加门禁

如果 MDF 前端需要调用 `invokeFunction` 查询数据、ID 转 code/name、补充报表参数或页面跳转参数，除 4.1 要素外，还必须明确：

1. 后端 API 是否已存在；不存在则由本 skill 生成 YonScript API。
2. API 入参结构。
3. API return 结构。
4. 平台包装后的前端回调路径，例如 `res.data.sectionCode`。

任一项不明确时，不得只生成 MDF 前端占位调用。

---

## 5. 输出要求

输出中应说明：

- 哪些协同能力未调用 skill，原因是什么。
- 哪些协同能力调用了 skill，缺口是什么。
