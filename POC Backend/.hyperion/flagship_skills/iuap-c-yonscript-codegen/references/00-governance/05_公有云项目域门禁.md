# 公有云项目域门禁

> **加载时机**：任何准备进入 `iuap-c-yonscript-codegen` 的请求，在真正生成代码前必须先过本门禁。
> **职责**：判断当前需求是否属于“公有云项目代码生成域”，以及进入本域后必须遵守的互斥规则、采集规则、禁止臆想规则。

---

## 1. 总原则

只要用户需求中**明确包含“公有云”**，或者当前会话/项目上下文已明确锁定为**公有云项目**，就必须优先进 `iuap-c-yonscript-codegen` 进行统一编排。

进入本域后：

- 所有后端实现主控制权只能由 `iuap-c-yonscript-codegen` 负责。
- 允许调用共用 skill 做信息采集或前端协同，但必须在优先进本 skill 后再按编排调用。
- 禁止再把后端代码生成控制权转交给任何 Java、本地化、业务集成代码生成 skill。

---

## 2. 准入识别规则

### 2.1 强阳性条件

满足任一条件，即必须优先进本 skill：

- 用户明确提到 `公有云`
- 当前会话上下文已锁定为公有云项目
- 当前项目背景已确认是公有云项目，且需求属于代码生成/扩展开发

### 2.2 公有云域内后端典型信号

以下信号用于加强判定，但**不能替代“公有云”总开关**：

- YonScript
- Rule脚本 / API脚本
- ObjectStore / openLinker / postman / invokeFunction
- afterAudit / afterUnaudit
- sendMessage / 友空间 / 短信 / 模板邮件
- YonSQL / safeJsonParse / Long字段失真

### 2.3 强互斥条件

如果已进入公有云项目域，则以下 skill **禁止再接管后端代码生成**：

- `iuap-c-server-codegen`
- 任何本地化部署 Java 后端 skill
- 任何生成 Java / Spring / Maven 代码的 skill
- 任何业务集成代码生成 skill，如：
  - `yonbip-c-arap-integration`
  - `yonbip-c-bd-integration`
  - `yonbip-c-exp-integration`

这些 skill 与 `iuap-c-yonscript-codegen` 在公有云后端域内是**互斥**关系。

### 2.4 公有云首入口判定矩阵

| 判定类型 | 判定条件 | 处理动作 | 说明 |
|---|---|---|---|
| **必须优先进** | 用户需求明确包含 `公有云` | 第一入口必须落到 `iuap-c-yonscript-codegen` | 这是首入口规则，不允许其他 skill 抢占首入口 |
| **必须优先进** | 当前会话/项目上下文已锁定为公有云项目 | 第一入口继续落到 `iuap-c-yonscript-codegen` | 会话一旦锁定，后续同域需求继续优先进入本 skill |
| **必须优先进** | 当前项目背景已确认是公有云项目，且需求属于代码生成/扩展开发 | 第一入口必须落到 `iuap-c-yonscript-codegen` | 即使用户本轮未重复说“公有云”，也不能让其他 skill 抢首入口 |
| **允许后置协同** | 已进入本 skill，且需要业务对象信息 | 由本 skill 调 `iuap-c-metadata-info` | 元数据 skill 只负责“查”，不能成为首入口 |
| **允许后置协同** | 已进入本 skill，且需要 OpenAPI 信息 | 由本 skill 调 `iuap-c-openapi-integration` | API 查询只能在本 skill 编排下发生 |
| **允许后置协同** | 已进入本 skill，且需要事件信息 / 事件订阅 API 信息 | 由本 skill 调 `iuap-c-event-integration` | 事件 skill 只做查询，不接管主编排 |
| **允许后置协同** | 已进入本 skill，且需要 MDF 前端实现 | 由本 skill 调 `iuap-c-mdf-codegen` | 前端可协同生成，但首入口和主编排仍归本 skill |
| **禁止首入口抢占** | 需求已明确是公有云项目，但其他共用 skill 先被调用 | 拒绝作为首入口，要求先回到 `iuap-c-yonscript-codegen` | 共用 skill 不能绕过本 skill 直接接管需求 |
| **禁止首入口抢占** | 需求已明确是公有云项目，但 Java / 本地化 / 业务集成后端 skill 先被调用 | 拒绝首入口接管 | 公有云后端主控制权与这些 skill 互斥 |
| **禁止首入口抢占** | 已进入本 skill 后，试图把后端代码生成主控制权转交给其他 skill | 禁止转交，仅允许后置协同查询/前端协同 | 可以协同，但不能失去本 skill 的主控地位 |

## 3. 共用 skill 的角色定义

以下 skill 在公有云域内只作为**能力依赖**，不作为主路由目标：

| skill | 角色 |
|---|---|
| `iuap-c-metadata-info` | 元数据查询器 |
| `iuap-c-openapi-integration` | OpenAPI 查询器 |
| `iuap-c-event-integration` | 事件信息查询器 |
| `iuap-c-mdf-codegen` | 前端 MDF 实现器 |

规则：

- 可以调用这些 skill 收集信息或生成前端代码。
- 但最终主编排者仍然是 `iuap-c-yonscript-codegen`。
- 最终后端实现仍然必须落回 YonScript/V8。

---

## 4. 采集优先于生成

在公有云域内，任何代码生成前必须先判断是否需要以下采集：

1. 主业务对象元数据
2. 参照元数据
3. OpenAPI 信息
4. 事件信息
5. MDF 前端依赖信息
6. YonSQL 四要素是否充分
7. OpenAPI / 事件 / MDF 协同信息是否充分

如果需要采集但未采集完成，**禁止进入生成阶段**。

补充：

- 生成任何 YonSQL、ObjectStore 查询、MDF 字段逻辑、规则脚本字段访问代码前，必须先做信息充分性判定。
- 如果 YonSQL 的 `uri`、`domain`、字段、查询条件都已明确且可追溯，可直接拼装；任一项不明确时，必须先有对应元数据查询结果。
- 如果请求中给出了业务对象名称或业务语义，必须先按名称/语义查元数据。
- 如果请求中给出了 URI，必须先按 URI 查元数据。
- 如果当前生成结果里出现硬编码的 URI/domain/字段，但没有对应元数据消费清单，视为违反门禁。
- 如果 OpenAPI 的 URL/method/request/response 不完整，必须先调 `iuap-c-openapi-integration`。
- 如果事件的 eventCode/报文/API 地址不完整，必须先调 `iuap-c-event-integration`。
- 如果 MDF 的页面实体/字段来源/交互方式不完整，必须先补元数据，必要时再调 `iuap-c-mdf-codegen`。

---

## 5. 禁止臆想

在公有云域内，以下内容必须依赖查询结果，禁止臆想：

- 业务对象 URI
- domain
- 字段名
- 子表 key
- 特征组编码
- 参照对象结构
- OpenAPI URL / method / request / response
- eventCode / 事件报文结构

如信息不完整，先采集，后生成。

---

## 6. 输出前必须声明的准入结论

进入生成阶段后，输出中必须至少隐含或显式满足以下判断：

- 当前需求已识别为公有云项目域
- 当前后端实现由 `iuap-c-yonscript-codegen` 统一编排
- 未转交任何 Java / 本地化 / 业务集成后端生成 skill
