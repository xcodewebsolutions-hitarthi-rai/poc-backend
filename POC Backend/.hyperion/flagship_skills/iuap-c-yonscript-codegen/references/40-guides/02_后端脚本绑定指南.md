## 绑定场景概览

| 绑定场景 | 脚本类型 | 基类 | 触发时机 | 典型用途 |
|---------|---------|------|---------|---------|
| 前端脚本调用 | API脚本 | `AbstractAPIHandler` | 前端主动调用 | 按钮点击、字段联动时查询后端数据 |
| YPD扩展点 | Rule脚本 | `AbstractTrigger` | 单据操作触发 | 保存前/后校验、提交前/后处理、审核后处理 |
| MDD规则链 | Rule脚本 | `AbstractTrigger` | 规则触发 | 数据变更后自动执行业务规则 |

## 前端脚本调用

最常用的绑定方式。前端通过 `invokeFunction` 调用后端API脚本。

### 脚本类型

API脚本（`AbstractAPIHandler`）

### 前端调用方式

**MDF框架：**
```javascript
cb.rest.invokeFunction('ATxxx.Module.apiCode', {
  key: 'value'
}, function (err, res) {
  if (err) {
    cb.utils.alert('调用失败: ' + err.message, 'error');
    return;
  }
  // 处理结果
});
```

**YNF框架：**
```javascript
storeRestInvokeFunction(rootStore, 'ATxxx.Module.apiCode', {
  key: 'value'
}, function (err, res) {
  if (err) {
    rootStore.utils.message.danger('调用失败: ' + err.message);
    return;
  }
  // 处理结果
}, { domainKey: '领域编码' });  // 跨领域时传入
```

### 脚本编码命名规范

后端API编码格式：`租户编码.模块名.函数名`

示例：`GT3734AT5.reportData.getVendors`

## YPD扩展点绑定

将Rule脚本绑定到YPD（YonBIP Platform Development）的扩展点上。

### 脚本类型

Rule脚本（`AbstractTrigger`）

### 常见扩展点

| 扩展点 | 触发时机 | 典型用途 |
|-------|---------|---------|
| 保存前 | 单据保存前 | 数据校验、自动赋值 |
| 保存后 | 单据保存后 | 同步数据、触发通知 |
| 提交前 | 单据提交前 | 提交校验 |
| 提交后 | 单据提交后 | 触发下游流程 |
| 审核前 | 单据审核前 | 审核校验 |
| 审核后 | 单据审核后 | 状态同步、通知 |

### 入参结构

```javascript
var AbstractTrigger = require('AbstractTrigger');
class MyTrigger extends AbstractTrigger {
  execute(context, param) {
    // context — 当前操作的上下文信息
    var action = context.action;          // 当前动作：save/submit/audit 等
    var billName = context.billName;     // 单据名称
    var domain = context.domain;         // 领域编码

    // param — 单据数据
    var bills = param.billDOs || (param.billDO ? [param.billDO] : []);
    var bill = bills[0];
    var billId = bill.id;

    return {};
  }
}
exports({ entryPoint: MyTrigger });
```

> 详细入参结构见 `../20-input/02_YPD扩展点入参.md`

## MDD规则链绑定

将Rule脚本绑定到MDD规则链中，在数据变更时自动执行。

### 脚本类型

Rule脚本（`AbstractTrigger`）

### 入参结构

```javascript
var AbstractTrigger = require('AbstractTrigger');
class MyTrigger extends AbstractTrigger {
  execute(context, param) {
    // context — 当前规则链触发的上下文信息
    var action = context.action;   // 动作：save/submit/audit
    var billnum = context.billnum; // 单据编码
    var name = context.name;       // 单据名称

    // param — 包含完整单据数据
    var bills = param.data || [];
    var bill = bills[0];
    var billId = bill.id;

    return {};
  }
}
exports({ entryPoint: MyTrigger });
```

> 详细入参结构见 `../20-input/01_MDD规则链入参.md`

### 使用原则

- 仅在用户明确要求时生成Rule脚本
- 默认优先使用API脚本（前端调用或YPD扩展点绑定）
- Rule脚本适用于无需前端交互、由数据变更自动触发的场景

## 脚本编码建议

| 场景 | 编码格式 | 示例 |
|------|---------|------|
| API脚本 | `GTxxx.Module.function` | `GT3734AT5.pub.getCustomer` |
| Rule脚本 | `GTxxx.Module.ruleName` | `GT3734AT5.rule.vendorApprove` |

> 脚本编码用于前端 `invokeFunction` 调用，或平台规则引擎绑定
