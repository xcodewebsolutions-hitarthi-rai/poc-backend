# 消息触达

> **触发词**：发邮件、邮件通知、邮件模板、抄送、sendMessage、模板邮件、友空间通知、短信
> **加载策略**：邮件/消息场景触发时整体加载（**单文件深度优化**，不分子文档）
> **API 入口**：平台内置 `sendMessage(messageInfo)` 函数
> **适用**：YonBIP 公有云/旗舰版，单据保存/编辑/按钮点击后主动发邮件；审批流/非审批流均支持

---

## 0. 名词定义（必读，先看这里）

> **作用**：建立统一术语认知。后续章节使用这些术语时，**含义锁定**。用户根据术语动态匹配/设置参数时，直接对照本表。

| 术语 | 类别 | 含义 | 数据来源 | 代码侧入参 |
|------|------|------|----------|------------|
| **`[OBJ#xxx]`** | **元数据占位符** | 邮件模板中基于**单据元数据字段**渲染的占位符。`xxx` 是单据元数据的字段编码（如 `code`、`memo`）| 单据元数据（自动从单据ID查询）| `messageInfo.others`（元数据专属参数）|
| **元数据参数** | 参数类型 | 渲染 `[OBJ#xxx]` 占位符所需的所有参数集合 | 单据元数据 + 上下文 | `others` 对象 |
| **`{{xxx}}` / `{{customField}}`** | **自定义占位符** | 邮件模板中由用户**自行定义**的占位符 | **业务变量**（手动传值）| `messageInfo.busiData`（普通模板参数）|
| **业务变量** | 数据来源 | 模板中**非元数据**的动态值（如审批人、金额、审批意见）| 业务上下文/手动传值 | `busiData` 对象 |
| **`templateCode`** | 模板标识 | 消息模板的**唯一编码**（在消息模板列表中复制）| 平台消息模板 | `messageInfo.templateCode` |
| **消息模板** | 资源 | 平台消息平台预配置的邮件内容模板（可含 `[OBJ#xxx]` 和 `{{xxx}}`）| 消息平台 → 消息模板菜单 | — |
| **`groupCode`** | 调用分组 | 调用分组的编码。**非审批流固定 `'businessprocess'`**| 平台固定 | `messageInfo.groupCode` |
| **`mailCc`** | 抄送人 | 邮件抄送收件人（**字符串**，多个用英文逗号分隔）| 模板固定 / 代码动态 | `messageInfo.mailCc` |
| **公式模板** | 模板类型 | 邮件模板中含有平台公式（求和、跨单据引用等）| 消息平台 → 模板编辑 | + 4 个参数（§5）|
| **元数据专属参数** | 必需参数 | 渲染 `[OBJ#xxx]` 必需的 8 个字段集合（domain/billId/busiObjId/tenantId/yhtToken/appCode/businessObjectCode/billNo）| 平台/单据/应用配置 | `others` 对象内部 |
| **`domainKey`** ⭐ | 公式模板专属 | 领域编码。**必须与 `others.domain` 完全一致**（同一来源：URL 的 `feDomainKey`）| 平台 URL/元数据 | `messageInfo.domainKey` |
| **`businessId`** ⭐ | 公式模板专属 | 单据主键ID。**String 类型**（平台已 String 化）| `request.data.id` | `messageInfo.businessId` |
| **`realDocumentId`** ⭐ | 公式模板专属 | 单据真实文档ID。一般同 `businessId`，部分单据不同（需查元数据）| `request.data.id` 或元数据 | `messageInfo.realDocumentId` |
| **`uri`** ⭐ | 公式模板专属 | 单据实体的**完整 URI**。**必须调 iuap-c-metadata-info 查**，禁止凭 `businessObjectCode` 推导 | **元数据** | `messageInfo.uri` |

### 0.1 关键区分（避免混淆）

```
┌──────────────────────────────────────────────────────────────┐
│ 邮件模板中的占位符分两类：                                      │
│                                                              │
│  ① [OBJ#code]、[OBJ#memo]                                     │
│     └─ 元数据占位符 → 自动从单据ID查元数据 → 入参: others      │
│                                                              │
│  ② {{customField}}、{{approverName}}                          │
│     └─ 自定义占位符 → 手动传业务变量 → 入参: busiData         │
│                                                              │
│ ⚠️ 千万别混：                                                 │
│   - 模板用 [OBJ#code]，代码传 busiData.code → 渲染失败        │
│   - 模板用 {{code}}，代码传 others → 渲染失败                │
└──────────────────────────────────────────────────────────────┘
```

### 0.2 入参与模板占位符的对应关系

| 模板占位符 | 必填入参 | 入参位置 | 来源 |
|------------|----------|----------|------|
| `[OBJ#code]`、`[OBJ#memo]` 等**元数据占位符** | `others` 完整 8 字段 | `messageInfo.others` | 单据元数据 + 平台上下文 |
| `{{xxx}}` 等**自定义占位符** | `busiData` | `messageInfo.busiData` | 业务上下文（手动传值）|
| 模板中**两者都有** | `others` + `busiData` 都必传 | 两者 | 两者 |
| 模板中**无占位符**（纯文本） | 至少 `busiData: {}` | `messageInfo.busiData` | — |
| 模板含**公式** | 上述 + 4 个公式专属参数 | `messageInfo` 顶层 | 单据id / 实体URI |

### 0.3 决策原则

- **看模板** → 决定用 `busiData` 还是 `others` 还是两者
- **看场景** → 决定 channel（mail/uspace/sms）
- **看用户** → 决定 `mailReceiver` / `mailCc` / `uspaceReceiver`

## 3. 场景 A：简单文本邮件

**适用**：邮件正文写死，不需要模板渲染

```javascript
var AbstractAPIHandler = require('AbstractAPIHandler');
class MyAPIHandler extends AbstractAPIHandler {
  execute(request) {
    var env = ObjectStore.env();
    var result = sendMessage({
      sysId: 'diwork',                          // 固定值
      tenantId: env.tenantId,                   // 必填
      mailReceiver: ['user@example.com'],       // 收件人（数组）
      channels: ['mail'],                       // 通道：邮件
      subject: '审批完成通知',                  // 邮件标题
      content: '您的单据已审批通过'              // 邮件正文（不支持 [OBJ#xxx]）
    });
    return {};
  }
}
exports({ entryPoint: MyAPIHandler });
```

**参数配置说明**：

| 参数 | 取值 | 说明 |
|---|---|---|
| `sysId` | `'diwork'` | 固定值，不可改 |
| `tenantId` | `env.tenantId` | 从 `ObjectStore.env()` 取，**不要硬编码** |
| `mailReceiver` | `['a@x.com', 'b@x.com']` | 数组格式（单人也必须数组） |
| `channels` | `['mail']` | 邮件固定值 |
| `subject` | 任意字符串 | 邮件标题 |
| `content` | 任意字符串 | **不支持 `[OBJ#xxx]` 渲染** |

## 4. 场景 B：模板邮件 ⭐（核心）

**适用**：邮件正文用平台消息模板（支持 `[OBJ#xxx]` 渲染单据元数据）

**前置准备**（必须）：
1. 配置邮件消息通道（消息通道菜单 → 新建 → 邮箱，测试连通成功）
2. 配置消息模板（消息模板菜单 → 新建，模板正文用 `[OBJ#code]`、`[OBJ#memo]` 等占位符）
3. 复制模板的 `templateCode`（如 `bizObject::approved##xeYPgv3p`）

### 4.1 完整实现

```javascript
var AbstractAPIHandler = require('AbstractAPIHandler');
class MyAPIHandler extends AbstractAPIHandler {
  execute(request) {
    console.error("前端传入单据数据：" + JSON.stringify(request));
    var env = ObjectStore.env();

    // ① 基础邮件配置
    var mailReceiver = ['user@example.com'];                            // 收件人
    var templateCode = 'bizObject::approved##xeYPgv3p';                  // 步骤②拿到的模板编码
    var channels = ['mail'];                                             // 通道
    var groupCode = 'businessprocess';                                   // 非审批流固定值

    // ② 普通模板参数（对应模板中非 [OBJ#xxx] 的自定义占位符）
    var busiData = {
      // 例如模板里有 [customField]，这里传 { customField: '值' }
    };

    // ③ 元数据核心参数（模板用 [OBJ#xxx] 时【必须传递】）
    var others = {
      domain: 'upu',                                                    // 领域编码（从 URL 的 feDomainKey 取）
      billId: request.data.id,                                          // 单据主键ID
      busiObjId: request.data.id,                                       // 业务对象ID（一般同 billId）
      tenantId: env.tenantId,                                           // 租户ID
      yhtToken: env.token,                                              // 平台访问令牌
      appCode: 'PU',                                                    // 应用编码
      businessObjectCode: 'upu.pu_pricesettlement',                     // 业务对象完整编码
      billNo: 'pu_pricesettlement'                                      // 单据编码（与业务对象编码后半段一致）
    };

    // ④ 组装 sendMessage 入参
    var messageInfo = {
      sysId: 'diwork',
      tenantId: env.tenantId,
      templateCode: templateCode,
      busiData: busiData,
      mailReceiver: mailReceiver,
      channels: channels,
      groupCode: groupCode,
      others: others
    };

    var result = sendMessage(messageInfo);
    return { msg: result };
  }
}
exports({ entryPoint: MyAPIHandler });
```

### 4.2 others 参数详解（高频踩坑点）

| 字段 | 取值来源 | 缺失后果 |
|---|---|---|
| `domain` | 浏览器 URL 的 `feDomainKey` 参数 | `[OBJ#xxx]` 无法解析 |
| `billId` | `request.data.id` | 单据字段取不到 |
| `busiObjId` | 同 `billId` | 单据字段取不到 |
| `tenantId` | `ObjectStore.env().tenantId` | 跨租户问题 |
| `yhtToken` | `ObjectStore.env().token` | 鉴权失败 |
| `appCode` | 应用基础信息页查看 | 路由失败 |
| `businessObjectCode` | 业务模型管理 → 业务对象 → 完整编码 | 模板渲染失败 |
| `billNo` | 与 `businessObjectCode` 后半段一致 | 模板渲染失败 |

### 4.3 前端触发

```javascript
// 前端脚本（可绑定在 afterSave / 自定义按钮事件中）
cb.rest.invokeFunction('GT.xxx.sendMail001', body, function (err, res) {
  console.log('调用返回结果：' + res);
  var d = safeJsonParse(res.msg, { longFields: [], lengthThreshold: 16 });
  alert(d.d.Msg);
});
```

## 5. 场景 C：公式模板（特殊）

**适用**：邮件模板中含有平台公式（如求和、引用其他单据字段等）

**与场景 B 的区别**：必须补充 4 个**公式专属参数**（`businessId`、`realDocumentId`、`domainKey`、`uri`）

### 5.0 公式参数元数据消费门禁 ⭐（生成代码前必走）

> **强约束**：4 个公式专属参数**全部依赖元数据**，禁止臆想任何一个。违反直接阻断。

```
门禁 C1: domainKey 必须与 others.domain 完全一致
         └─ 来源：URL 的 feDomainKey 参数
         └─ 校验：domainKey === domain 必须 true

门禁 C2: businessId 从 request.data.id 取
         └─ 来源：前端传入的单据主键
         └─ 类型：String（平台已 String 化）

门禁 C3: realDocumentId 一般同 businessId
         └─ 部分单据可能不同（如多态单据、关联单据）
         └─ 如果业务明确有 realDocumentId 字段，查元数据确认

门禁 C4: uri 必须调 iuap-c-metadata-info 查
         └─ 来源：元数据 _entityInfo.uri（如 'upu.pu_pricesettlement'）
         └─ ❌ 禁止凭 businessObjectCode 推导
         └─ ❌ 禁止用 'domain.billNo' 拼装（如 'upu.pu_pricesettlement' ≠ domain串+billNo）

门禁 C5: businessObjectCode 必须调 iuap-c-metadata-info 查
         └─ 来源：元数据 _entityInfo.code 或业务对象菜单
         └─ 格式：完整限定名（如 'upu.pu_pricesettlement'）

门禁 C6: billNo 从 businessObjectCode 后半段截取
         └─ 规则：取 '.' 后面的部分（如 'pu_pricesettlement'）
         └─ 校验：businessObjectCode = appCode + '.' + billNo

门禁 C7: 公式参数与 others 域不冲突
         └─ domainKey === domain（共享同一来源）
         └─ businessId / busiObjId 可相同或不同（视业务确定）
```

### 5.1 完整实现（含门禁 C 参数获取）

```javascript
var AbstractAPIHandler = require('AbstractAPIHandler');
class MyAPIHandler extends AbstractAPIHandler {
  execute(request) {
    console.error("前端传入单据数据：" + JSON.stringify(request));
    var env = ObjectStore.env();

    // ① 基础邮件配置（同场景 B）
    var mailReceiver = ['user@example.com'];
    var templateCode = 'bizObject::approved##xeYPgv3p';
    var channels = ['mail'];
    var groupCode = 'businessprocess';
    var busiData = {};

    // ② 元数据专属参数（同场景 B）
    var others = {
      domain: 'upu',                                // 门禁 C1: URL 的 feDomainKey
      billId: request.data.id,
      busiObjId: request.data.id,
      tenantId: env.tenantId,
      yhtToken: env.token,
      appCode: 'PU',                                // 门禁 C6: 应用编码
      businessObjectCode: 'upu.pu_pricesettlement', // 门禁 C5: 业务对象完整编码
      billNo: 'pu_pricesettlement'                  // 门禁 C6: businessObjectCode 后半段
    };

    // ③ 公式模板参数获取（必须查元数据）
    var businessId = String(request.data.id);                       // 门禁 C2: 单据主键
    var realDocumentId = String(request.data.realDocumentId || request.data.id);  // 门禁 C3: 兜底同 businessId
    var domainKey = others.domain;                                  // 门禁 C1: 必须与 domain 一致
    // ⚠️ 门禁 C4: uri 必须从 iuap-c-metadata-info 获取（禁止臆想）
    var uri = 'upu.pu_pricesettlement';  // 预留，实际从元数据 _entityInfo.uri 取

    // ④ 公式参数一致性校验（门禁 C1 运行时检查）
    if (domainKey !== others.domain) {
      throw new Error('【邮件公式】domainKey(' + domainKey +
        ') 与 domain(' + others.domain + ') 不一致');
    }

    // ⑤ 组装 sendMessage（完整参数）
    var messageInfo = {
      sysId: 'diwork',
      tenantId: env.tenantId,
      templateCode: templateCode,
      busiData: busiData,
      mailReceiver: mailReceiver,
      channels: channels,
      groupCode: groupCode,
      others: others,
      // 公式模板额外 4 个参数（门禁 C1-C4）
      businessId: businessId,
      realDocumentId: realDocumentId,
      domainKey: domainKey,
      uri: uri
    };

    try {
      var result = sendMessage(messageInfo);
      console.error("邮件发送结果:" + result);
      return { msg: result };
    } catch (ex) {
      console.error("邮件发送异常:" + ex + ", stack:" + (ex.stack || '无'));
      throw ex;
    }
  }
}
exports({ entryPoint: MyAPIHandler });
```

### 5.2 公式参数与 others 域的关系映射

```
┌──────────────────────────────────────────────────────────────────┐
│                公式参数  ←→  others 域 映射                       │
├──────────────┬───────────────────────┬──────┬───────────────────┤
│ 公式参数     │ 来源                   │ 必含 │ 校验规则           │
├──────────────┼───────────────────────┼──────┼───────────────────┤
│ domainKey   │ others.domain          │ ✅    │ 必须 === domain     │
│ businessId   │ request.data.id        │ ✅    │ String 类型         │
│ realDocumentId│ request.data.id（兜底）│ ✅    │ 一般 = businessId   │
│ uri          │ **元数据**              │ ✅    │ 禁止臆想           │
│ businessObj  │ **元数据**              │ ✅    │ 完整限定名          │
│ appCode      │ 应用编码                │ ✅    │ 与 others 一致      │
│ billNo       │ businessObjectCode 后半段│ ✅   │ appCode + '.' + billNo│
│ busiObjId   │ request.data.id          │ ✅    │ 可 = businessId    │
│ billId       │ request.data.id          │ ✅    │ 可 = businessId    │
└──────────────┴───────────────────────┴──────┴───────────────────┘
```

### 5.3 快速自查（部署前必跑）

```javascript
// 复制到脚本末尾，会自动在校验点失败
if (typeof domainKey !== 'string') throw new Error('domainKey 必须是字符串');
if (domainKey !== others.domain) throw new Error('domainKey 与 domain 不一致:' + domainKey + ' vs ' + others.domain);
if (typeof businessId !== 'string') throw new Error('businessId 必须是字符串:' + typeof businessId);
if (typeof realDocumentId !== 'string') throw new Error('realDocumentId 必须是字符串:' + typeof realDocumentId);
if (!uri || typeof uri !== 'string') throw new Error('uri 为空或非字符串');
console.error('【邮件公式】门禁 C1-C7 全部通过');
```

⚠️ **如果模板含公式但没传这 4 个参数，邮件不会报错但公式不计算**——避坑指南见 [§ 10](#10-避坑指南必读)

## 6. 场景 D：邮件抄送

**适用**：除主收件人外，抄送给其他人

**两种方式**：

### 6.1 模板固定抄送（推荐）

在消息模板配置中直接设置抄送人（模板中"收件人"或"抄送"字段），无需改代码。

### 6.2 代码动态抄送

```javascript
var messageInfo = {
  sysId: 'diwork',
  tenantId: env.tenantId,
  templateCode: templateCode,
  busiData: busiData,
  mailReceiver: ['zhangsan@example.com'],            // 主收件人（数组）
  mailCc: 'lisi@example.com,wangwu@example.com',     // 抄送人（字符串，逗号分隔）
  channels: channels,
  groupCode: groupCode,
  others: others
};
```

**类型说明**：`mailCc` 是**字符串**类型，多个邮箱用英文逗号拼接；不要传数组。

**合并规则**：模板中配置的抄送人 + 代码中 `mailCc` 合并生效，系统自动去重。

### 6.3 根据业务动态设置抄送人

```javascript
execute(request) {
  var billAmount = request.data.amount;
  var mailCc = '';

  if (billAmount > 10000) {
    mailCc = 'cfo@example.com,manager@example.com';
  } else if (billAmount > 5000) {
    mailCc = 'manager@example.com';
  } else {
    mailCc = 'supervisor@example.com';
  }

  // 也可从 request.data.ccReceivers 接收前端传入（字符串）
  if (request.data.ccReceivers) {
    mailCc = mailCc ? mailCc + ',' + request.data.ccReceivers : request.data.ccReceivers;
  }

  // ... 组装 messageInfo，mailCc 直接传字符串
}
```

## 7. 场景 E：友空间工作通知

**适用**：推送消息到友空间 APP

```javascript
var AbstractAPIHandler = require('AbstractAPIHandler');
class MyAPIHandler extends AbstractAPIHandler {
  execute(request) {
    var uspaceReceiver = ['a2b307e9-2046-485d-8e71-b07d89d07d60'];  // 友空间用户ID

      sysId: 'diwork',
      tenantId: ObjectStore.env().tenantId,
      uspaceReceiver: uspaceReceiver,
      channels: channels,

      content: request.content,
      groupCode: 'prewarning'                          // 友空间常用分组

    var result = sendMessage(messageInfo);
    return {};
  }
}
exports({ entryPoint: MyAPIHandler });
```

**说明**：`uspaceReceiver` 是友空间**用户ID**（不是邮箱），从用户管理/友空间后台获取。

## 8. 场景 F：短信通知

```javascript
sendMessage({
  sysId: 'diwork',
  tenantId: env.tenantId,
  smsReceiver: ['13800138000'],
  channels: ['sms'],
  subject: '验证码',
  content: '您的验证码是 123456，5 分钟内有效。'
});
```

⚠️ 短信通道需要单独配置，且部分运营商需要审核签名/模板。

## 9. sendMessage 全量参数速查

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `sysId` | string | ✅ | 系统ID，固定 `'diwork'` |
| `tenantId` | string | ✅ | 租户ID，`ObjectStore.env().tenantId` |
| `channels` | array | ✅ | 渠道列表：`['mail']` / `['uspace']` / `['sms']` |
| `mailReceiver` | array | 邮件时必填 | 收件人邮箱数组 |
| `uspaceReceiver` | array | 友空间时必填 | 友空间用户ID数组 |
| `smsReceiver` | array | 短信时必填 | 手机号数组 |
| `mailCc` | string | ❌ | 抄送邮箱（**字符串**，多个用英文逗号分隔）|
| `subject` | string | 模板邮件时必填 | 邮件标题 |
| `content` | string | 简单邮件时必填 | 邮件正文（不支持 `[OBJ#xxx]`）|
| `templateCode` | string | 模板邮件时必填 | 消息模板编码 |
| `busiData` | object | ✅ | 普通模板参数（`{}` 空对象也行）|
| `groupCode` | string | ❌ | 调用分组，**非审批流固定 `'businessprocess'`** |
| `others` | object | 模板含 `[OBJ#xxx]` 时必填 | 元数据专属参数（见 §3.2）|
| `businessId` | string | 公式模板时必填 | 单据id |
| `realDocumentId` | string | 公式模板时必填 | 单据id |
| `domainKey` | string | 公式模板时必填 | 与 `domain` 一致 |
| `uri` | string | 公式模板时必填 | 实体完整URI |

## 10. 避坑指南（必读）

### 10.1 通用坑（任何场景通用）

| # | 坑 | 现象 | 修复 |
|---|---|---|---|
| 1 | 邮件通道没测试连通 | 邮件发送失败无明确错误 | 通道配置后**必须**点"测试发送"成功 |
| 2 | `groupCode` 写成 `'approve'` | 非审批流邮件发送失败 | **固定** `'businessprocess'` |
| 3 | 模板用 `[OBJ#xxx]` 但没传 `others` | 邮件收到但占位符**原样显示** | 补充 `others`（§3.2）|
| 4 | `mailReceiver` 不是数组 | 收件人为空 | 必须是 `['xxx@xx.com']` |
| 5 | `domain` / `businessObjectCode` 手写 | 元数据渲染失败 | **从 URL/业务对象页复制**，不手写 |
| 6 | 硬编码 `tenantId` | 切换租户失败 | 用 `ObjectStore.env().tenantId` |
| 7 | `busiData` 字段名与模板不一致 | 模板渲染失败 | 模板占位符 `{{xxx}}` ↔ 代码 `busiData.xxx` 一致 |
| 8 | 没用 `try-catch` 包 `sendMessage` | 异常阻断业务流程 | §11 异常处理模板 |

### 10.2 公式模板专属坑 ⭐（最易踩）

| # | 坑 | 现象 | 修复 |
|---|---|---|---|
| 9 | 公式模板没传 4 个参数 | 邮件收到但**公式不计算**（不报错）| 补充 `businessId`/`realDocumentId`/`domainKey`/`uri`（§5.0）|
| 10 | `domainKey` 与 `others.domain` 不一致 | 公式**部分计算或全错** | §5.1 运行时校验 `domainKey === domain` |
| 11 | `uri` 凭 `businessObjectCode` 推导 | 公式引擎找不到实体，元数据缺失 | 必须调 iuap-c-metadata-info 查 `_entityInfo.uri`（**门禁 C4**）|
| 12 | `businessId` 传 Long 数字 | 平台 String 化后类型不匹配 | 强制 `String(request.data.id)`（**门禁 C2**）|
| 13 | `realDocumentId` 当成 `businessId` 同义 | 部分单据（如多态单据）公式错 | 优先取 `request.data.realDocumentId`，兜底取 `request.data.id`（**门禁 C3**）|
| 14 | `uri` 写 `'upu.pu_pricesettlement'` 但模板用 `'upu_pricesettlement'` | 公式引擎找不到实体 | `uri` 必须与 `templateCode` 中的实体标识**完全一致** |

## 11. 异常处理模板（推荐）

**规则**：代码性错误/网络异常 → 抛异常阻断；业务正常日志 → 打印即可

```javascript
try {
  var result = sendMessage(messageInfo);
  console.error("邮件发送结果:" + result);
  return { msg: result };
} catch (ex) {
  console.error("邮件发送异常:" + ex + ", stack:" + (ex.stack || '无'));
  throw ex;  // 抛异常阻断业务
}
```

## 14. 实际业务场景：从客户档案查询联系人并发送邮件

> 本场景基于实际生产代码，展示如何从客户档案查询联系人信息，并根据业务规则发送邮件。

### 14.1 业务背景

**场景**：审批后自动发送应收对账单邮件给客户
**流程**：
1. 从客户档案查询联系人信息（使用YonSQL）
2. 获取SOA to Email和SOA cc Email
3. 构建邮件模板参数
4. 批量发送邮件

### 14.2 完整实现

```javascript
var AbstractAPIHandler = require('AbstractAPIHandler');
class MyAPIHandler extends AbstractAPIHandler {
  execute(request) {
    try {
      this.log('开始发送应收对账单邮件');

      var templateCode = request.templateCode;
      var billData = request.billData;

      if (!templateCode) {
        return { success: false, message: '消息模板编码不能为空' };
      }

      if (!billData || !Array.isArray(billData) || billData.length === 0) {
        return { success: false, message: '请选择应收对账单数据' };
      }

      var env = ObjectStore.env();
      var results = [];
      var successCount = 0;
      var failCount = 0;

      // 遍历选中的应收对账单数据
      for (var i = 0; i < billData.length; i++) {
        var billItem = billData[i];

        try {
          this.log('处理第' + (i + 1) + '条数据，客户ID: ' + billItem.customerId);

          // 1. 查询客户联系人信息（使用YonQL业务对象方式）
          // 传入客户ID、项目ID（可能为空）和组织ID（可能为空）
          var contacts = this.queryCustomerContacts(billItem.customerId, billItem.projectId, billItem.financeOrgId);

          // 2. 获取SOA to Email和SOA cc Email
          var emailInfo = this.getSoaEmails(contacts);

          if (emailInfo.toEmails.length === 0) {
            this.log('客户ID ' + billItem.customerId + ' 未找到接收人邮箱');
            failCount++;
            results.push({
              billId: billItem.id,
              success: false,
              message: '未找到接收人邮箱',
            });
            continue;
          }

          // 3. 构建模板参数（包含OBJ#id格式）
          var messageInfo = this.buildMessageInfo(templateCode, emailInfo.toEmails, emailInfo.ccEmails, billItem, env);

          // 4. 发送邮件
          var sendResult = this.sendMail(messageInfo);

          if (sendResult) {
            successCount++;
            results.push({
              billId: billItem.id,
              success: true,
              message: '发送成功',
            });
          } else {
            failCount++;
            results.push({
              billId: billItem.id,
              success: false,
              message: '发送失败',
            });
          }
        } catch (itemError) {
          this.log('处理单据ID ' + billItem.id + ' 异常: ' + itemError.message);
          failCount++;
          results.push({
            billId: billItem.id,
            success: false,
            message: '处理异常: ' + itemError.message,
          });
        }
      }

      this.log('邮件发送完成，成功: ' + successCount + ', 失败: ' + failCount);

      return {
        success: true,
        data: {
          total: billData.length,
          successCount: successCount,
          failCount: failCount,
          details: results,
        },
      };
    } catch (e) {
      this.log('发送邮件异常: ' + e.message);
      return {
        success: false,
        message: '发送邮件失败: ' + e.message,
      };
    }
  }
  log(message) {
    console.error('【MyAPIHandler】' + message);
  }
  queryCustomerContacts(customerId, projectId, orgId) {
    var contacterUri = 'aa.merchant.Contacter';
    var merchantDomain = 'productcenter';
    try {
      var yonSql = 'select id, merchantId, email, isDefault, contacterCharacter.soatoemail as soatoemail, contacterCharacter.soaccemail as soaccemail from ' + contacterUri + ' ' + "where merchantId = '" + customerId + "'";
      if (projectId) {
        yonSql += " and contacterCharacter.project = '" + projectId + "'";
      } else {
        yonSql += ' and contacterCharacter.project = null';
      }
      if (orgId) {
        yonSql += " and contacterCharacter.Organization = '" + orgId + "'";
      } else {
        yonSql += ' and contacterCharacter.Organization = null';
      }
      this.log('查询客户联系人YonSQL: ' + yonSql);
      var result = ObjectStore.queryByYonQL(yonSql, merchantDomain);
      this.log('客户联系人查询结果: ' + JSON.stringify(result));
      return result || [];
    } catch (e) {
      this.log('查询客户联系人异常: ' + e.message);
      console.error('查询客户联系人异常堆栈: ' + (e.stack || '无'));
      return [];
    }
  }
  getSoaEmails(contacts) {
    var toEmails = [];
    var ccEmails = [];
    contacts.forEach(function (contact) {
      if (contact.soatoemail) {
        toEmails.push(contact.soatoemail);
      }
      if (contact.soaccemail) {
        ccEmails.push(contact.soaccemail);
      }
      if (toEmails.length === 0 && contact.email) {
        if (contact.isDefault === '1' || contact.isDefault === true || contact.isDefault === 'true') {
          toEmails.push(contact.email);
        } else {
          ccEmails.push(contact.email);
        }
      }
    });
    return {
      toEmails: toEmails,
      ccEmails: ccEmails.join(','),
    };
  }
  buildMessageInfo(templateCode, toEmails, ccEmails, billItem, env) {
    var billDomain = 'yonbip-fi-earap';
    var billNo = 'ARStatement';
    var others = {
      domain: billDomain,
      billId: billItem.id,
      busiObjId: billItem.id,
      tenantId: env.tenantId,
      yhtToken: env.token,
      appCode: 'EAR',
      businessObjectCode: 'ARStatement',
      billNo: billNo,
    };
    var busiData = {
      customerId: billItem.customerId,
      projectId: billItem.projectId,
      orgId: billItem.orgId,
      financeOrgId: billItem.financeOrgId,
    };
    var messageInfo = {
      sysId: 'diwork',
      tenantId: env.tenantId,
      templateCode: templateCode,
      busiData: busiData,
      mailReceiver: toEmails,
      mailCc: ccEmails,
      channels: ['mail'],
      groupCode: 'businessaction',
      language: 'en_US',
      others: others,
    };
    return messageInfo;
  }
  sendMail(messageInfo) {
    this.log('发送消息请求体: ' + JSON.stringify(messageInfo));
    try {
      var result = sendMessage(messageInfo);
      this.log('邮件发送结果: ' + result);
      return result;
    } catch (ex) {
      this.log('邮件发送异常: ' + ex + ', stack: ' + (ex.stack || '无'));
      throw ex;
    }
  }
}
exports({ entryPoint: MyAPIHandler });
```

### 14.3 关键要点

| 要点 | 说明 |
|------|------|
| **特征组字段查询** | 使用 `contacterCharacter.soatoemail` 查询特征组字段，并起别名方便后续使用 |
| **YonSQL条件拼接** | 根据项目ID和组织ID是否存在，动态拼接SQL条件 |
| **邮箱优先级** | 优先使用特征组字段 `soatoemail` 和 `soaccemail`，其次使用默认 `email` 字段 |
| **批量发送** | 遍历单据列表，逐条发送邮件，记录成功/失败状态 |
| **错误处理** | 每条单据独立try-catch，避免一条失败影响其他单据 |
