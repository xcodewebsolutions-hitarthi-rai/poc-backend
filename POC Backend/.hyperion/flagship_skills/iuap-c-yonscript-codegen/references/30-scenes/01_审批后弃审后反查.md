# 审批后/弃审后 only-id 场景（5 步反查法）

> **加载时机**：用户需求命中"审批后"、"弃审后"、"审核后"、"反审核后"、`afterAudit`、`afterUnaudit` 触发词
> **场景定位**：BIP 平台 rule 规则函数在审核/反审核事件中**只回传 id**，`param.data` / `param.billDOs` 中**取不到完整单据数据**，必须用 YonSQL 反查

---

## 一、场景识别（决策表）

| 事件 | context.action | YPD 扩展点绑定 | param.data 可用 | 必须用 5 步反查法 |
|------|---------------|---------------|----------------|-----------------|
| 审核后 | `"audit"` | afterAudit | ❌ 部分场景为空 | ✅ |
| 反审核后 | `"unaudit"` | afterUnaudit | ❌ 部分场景为空 | ✅ |
| 提交后 | `"submit"` | afterSubmit | ⚠️ 数据完整 | 视需求 |
| 保存后 | `"save"` | afterSave | ✅ 数据完整 | ❌ 不需要 |

**关键判断**：
- 若 `param.data` 或 `param.billDOs` 为空 / 长度 0 / 元素为 `null` → 必须用 5 步反查法
- 若有数据但字段不全（如只有 id 缺业务字段）→ 仍走 5 步反查法

## 二、billId 提取（4 种来源，按优先级）

```javascript
function extractBillId(context, param) {
    // 优先级 1: context.ids（MDD 规则链常用）
    if (context && context.ids && context.ids.length > 0) {
        return context.ids[0];
    }
    // 优先级 2: param.ids（YPD 扩展点）
    if (param && param.ids && param.ids.length > 0) {
        return param.ids[0];
    }
    // 优先级 3: param.billDOs[0].id（部分 YPD 场景）
    if (param && param.billDOs && param.billDOs[0] && param.billDOs[0].id) {
        return param.billDOs[0].id;
    }
    // 优先级 4: param.data[0].id（MDD 规则链兜底）
    if (param && param.data && param.data[0] && param.data[0].id) {
        return param.data[0].id;
    }
    // 优先级 5: BPM 完成事件
    if (param && param.baseBillContext && param.baseBillContext.extProps) {
        var bpmParam = param.baseBillContext.extProps.bpmcompleteParam;
        if (bpmParam && bpmParam.businessKey) {
            return bpmParam.businessKey.split('_').pop();
        }
    }
    return null;
}
```

**billId 仍为 null → 必须抛错**，不进入 Step 2：
```javascript
var billId = extractBillId(context, param);
if (!billId) {
    throw new Error('【MyTrigger】审批后场景：billId 提取失败（context.ids / param.ids / param.billDOs / param.data 均为空）');
}
```

## 三、5 步反查法（核心）

### Step 1: 元数据发现（强制）

**目的**：拿到主表 URI / 子表 key / 子表 URI / 参照 refUri / 特征组 attributes

```bash
# CLI 调用
python scripts/ultimate_metadata_query.py \
  --allbillname "供应商状态变更单" \
  --query-uri "cpu-supplymgr.supplystatuschange.SupplyStatusChange" \
  --is-include-sub Y \
  --format structured
```

**元数据消费清单**（必须列出）：
| 元数据路径 | 含义 | 用途 |
|-----------|------|------|
| `_entityInfo.uri` | 主表 URI | Step 2 SQL FROM |
| `_entityInfo.domain` | 领域编码 | `queryByYonQL` 第二参数 |
| `attributes[name=xxx]` | 字段定义 | Step 2 SQL SELECT |
| `tables.<key>.uri` | 子表 URI | Step 3 SQL FROM |
| `tables.<key>.attributes[name=xxx]` | 子表字段 | Step 3 SQL SELECT |
| `attributes[name=xxx].refUri` | 参照 URI | Step 5 SQL FROM |
| `characterGroups.<g>.attributes` | 特征组字段 | 特征组 SQL 拼装 |

**失败处理**：元数据查询失败必须抛错，禁止凭经验拼 SQL。

### Step 2: 主表反查

```javascript
// 字段名必须从元数据 attributes[].name 取
var mainSql = `select id, code, transType, orgId
               from \`cpu-supplymgr.supplystatuschange.SupplyStatusChange\`
               where id = '${billId}' and dr = 0`;
var mainList = ObjectStore.queryByYonQL(mainSql, 'cpu-supplymgr');
```

**字段命名转换**（详见 reference 21）：
- 主表 primitive 字段：直接写 `code`, `name`, `id`
- 主表 Reference 字段：拼装为 `transType`, `orgId`（按元数据 name 取，不是 refUri）

### Step 3: 子表反查

```javascript
// 子表 key 从元数据 tables.<key> 取，禁止臆想
var detailSql = `select id, vendorId, userDefineCharacter.Tsedate as tsedate
                 from \`cpu-supplymgr.supplystatuschange.SupplyStatusDetail\`
                 where changeId = '${billId}' and dr = 0`;
var detailList = ObjectStore.queryByYonQL(detailSql, 'cpu-supplymgr');
```

**特征组取值**：
- 特征组前缀（`userDefineCharacter`）必须从元数据 `attributes[name=userDefineCharacter]` 确认 `type == '特征组'`
- 特征编码（`Tsedate`）必须从 `characterGroups.<g>.attributes[].name` 取
- 完整路径：`userDefineCharacter.Tsedate`

### Step 4: 孙表反查（按需）

```javascript
// 孙表 key 从 tables.<key>.tables.<孙key> 取（V2.1 元数据支持）
var grandChildSql = `select id, status
                     from \`<子表URI>\`.<孙表URI>
                     where parentId = '${grandParentId}' and dr = 0`;
```

### Step 5: 参照档案反查（按需）

**触发条件**：脚本中需要展示参照字段的 code / name，而非仅 id。

```javascript
// 1. 收集所有参照 id
var transTypeIds = mainList.map(function (item) { return item.transType; });
// 2. 查参照档案（URI 从 refUri 取）
var transTypeSql = `select id, code, name
                    from \`bd.bill.TransType\`
                    where id in (${transTypeIds.map(function (id) { return "'" + id + "'"; }).join(',')})`;
var transTypeList = ObjectStore.queryByYonQL(transTypeSql, 'transtype');
```

**注意**：
- 参照档案 URI 必须从 `attributes[name=xxx].refUri` 取
- 拼装前必须先用 iuap-c-metadata-info 查参照档案的 attributes，确认含 `code` / `name` 字段
- 禁止用 `_code` / `_name` 后缀拼装（拼装到 JOIN ON 时才用，见 reference 21）

## 四、字段命名契约（指向 reference 21）

> **所有字段名取值规则已统一在 [../10-common/03_字段命名契约.md](../10-common/03_字段命名契约.md) 中维护**。
> 本节仅作为 quick reference，详细决策表请查阅 reference 21。

| 场景 | 元数据来源 | 拼装示例 |
|------|-----------|---------|
| 主表 primitive | `attributes[].name` | `select code, name from ...` |
| 主表 Reference | `attributes[].name` | `select transType, orgId from ...` |
| 特征组 primitive | `characterGroups.<g>.attributes[].name` | `select userDefineCharacter.Tsedate from ...` |
| 特征组 Reference | 二次查 `refUri` 参照元数据 | `select vendorCharacter.服务结束日期_code from ...` |
| 子表 key | `tables.<key>` | `from \`...\` where changeId = '...'` |
| 子表 primitive | `tables.<key>.attributes[].name` | `select {alias}.id, {alias}.vendorId` |
| 参照档案字段 | 二次查 `refUri.attributes` | 验证 `code` / `name` 字段存在 |

## 五、禁止臆想清单（强约束）

> 违反任何一条必须抛错，不允许"reasonable guess"。

| # | 场景 | 错误示例 | 正确做法 |
|---|------|---------|---------|
| 1 | 子表 key 不在 `tables` 中 | 凭经验写 `detailList` | 抛错"元数据未返回子表 {key}，请先调 iuap-c-metadata-info" |
| 2 | 字段名不在 `attributes` 中 | 写 `ext_field` | 抛错"元数据未返回字段 {name}" |
| 3 | 特征编码不在 `characterGroups.attributes` 中 | 写 `userDefineCharacter.XX` | 抛错"特征组 {group} 不含 {code}，禁止臆想" |
| 4 | 参照 `refUri` 缺失 | 写 `_code` 兜底 | 抛错"字段 {name} 类型为 Reference 但无 refUri" |
| 5 | 元数据 skill 调用失败 | 继续拼 SQL | 抛错"元数据查询失败，禁止凭经验拼 SQL" |
| 6 | 跨实体写错特征组字段 | `vendorCharacterDefine.Tsedate`（Tsedate 实际是 SupplyStatusDetail 的特征）| 二次查目标实体元数据，确认字段存在 |

## 六、完整 YonScript 模板

> **框架严格遵循**：[SKILL.md](../SKILL.md) 规定的 `var AbstractTrigger → class MyTrigger → execute → return {} → exports`。
> **文件名可按业务命名**，如 `SupplyChgApprRule.js`。

```javascript
var AbstractTrigger = require('AbstractTrigger');
class MyTrigger extends AbstractTrigger {
    execute(context, param) {
        // ===== Step 1: 提取 billId =====
        var billId = extractBillId(context, param);
        if (!billId) {
            throw new Error('【MyTrigger】审批后场景：billId 提取失败');
        }
        console.error('【MyTrigger】单据ID:' + billId);

        // ===== Step 2: 元数据发现（强制）=====
        // ⚠️ 必须先调 iuap-c-metadata-info 拿到主表 URI / 子表 key / 特征组编码
        // 失败必须抛错，不进入 Step 3
        // （伪代码：实际由大模型根据元数据输出动态生成以下变量）
        // var mainMeta = metadata.<主表key>;            // e.g. cpu_supply_status_change
        // var subMeta = mainMeta.tables.<子表key>;     // e.g. cpu_supply_status_detail
        // var charMeta = subMeta.characterGroups.<g>;  // e.g. userDefineCharacter
        // var refUris = mainMeta.attributes.filter(a => a.type === 'Reference').map(a => a.refUri);

        // ===== Step 3: 主表反查 =====
        var mainSql = `select id, code, transType, orgId
                       from \`<主表URI>\`
                       where id = '${billId}' and dr = 0`;
        console.error('【MyTrigger】主表SQL:' + mainSql);
        var mainList = ObjectStore.queryByYonQL(mainSql, '<domainKey>');
        if (!mainList || mainList.length === 0) {
            console.error('【MyTrigger】主表无数据,跳过');
            return {};
        }

        // ===== Step 4: 子表反查（含特征组）=====
        var subSql = `select id, <子表字段>, userDefineCharacter.<特征编码> as alias
                      from \`<子表URI>\`
                      where changeId = '${billId}' and dr = 0`;
        var subList = ObjectStore.queryByYonQL(subSql, '<domainKey>');
        if (!subList || subList.length === 0) {
            return {};
        }

        // ===== Step 5: 参照档案反查（按需）=====
        var refIds = mainList.map(function (item) { return item.<参照字段>; });
        var refSql = `select id, code, name
                      from \`<参照URI>\`
                      where id in (${refIds.map(function (id) { return "'" + id + "'"; }).join(',')})`;
        var refList = ObjectStore.queryByYonQL(refSql, '<参照domainKey>');

        // ===== 业务逻辑 =====
        // ...

        return {};
    }
}
exports({ entryPoint: MyTrigger });
```

## 七、常见错误 vs 正确写法

| ❌ 错误 | ✅ 正确 |
|--------|--------|
| `var billData = param.data[0];` 假定 data 完整 | 走 5 步反查法，不依赖 data |
| `select * from cpu_supply_status_detail` 全字段 | 仅 select 元数据返回的字段 |
| 凭经验写子表 URI `cpu-supplymgr...Detail` | 先查元数据取 `tables.<key>.uri` |
| 写 `vendorCharacterDefine.Tsedate`（跨实体写错）| 二次查目标实体元数据 |
| `param.data` 缺失时静默 `return {}` | 抛错，让上游感知 |
| 用 `dbColumnName` 拼 SQL（`iOrgId`）| 用 `attributes[].name`（`orgId`）|
| 参照字段写 `supplierId.code`（拼装到 SQL 误用）| 二次拉取参照档案后用 `supplierId_code` 形式做业务映射 |

## 九、Step 7：Long 字段精度防御（强制）

> **新增于 2026-06-04**：5 步反查法拿到 billId 后，若后续走 `ObjectStore.openLinker` / `ObjectStore.postman` / `queryByYonQL`，**必须**对返回的 Long 字段做精度防御。
> 完整规范见 [../00-governance/01_技术规范.md §规范8](../00-governance/01_技术规范.md#规范8long-字段精度防御新增)。
> 工具函数与原理见 [../10-common/04_Long精度防御.md](../10-common/04_Long精度防御.md)。

### 9.1 路径风险矩阵（审批后场景）

| # | 步骤 | 路径 | 失真风险 | 防御方法 |
|---|------|------|---------|---------|
| 1 | Step 1 提取 billId | `param.data[0].id` | ✅ 平台保护（String） | 直接用 String，无需处理 |
| 2 | Step 2-3 反查 | `ObjectStore.queryByYonQL` 返回 | ❌ id 是 Number | 详见 §9.2 |
| 3 | Step 4 业务调用 | `ObjectStore.openLinker` 返回字符串 | ❌ 必失真 | safeJsonParse |
| 4 | Step 4 跨租户 | `ObjectStore.postman` 返回字符串 | ❌ 必失真 | safeJsonParse |

### 9.2 queryByYonQL 返回的 Long 字段防御

```javascript
// YonQL 端：默认不用 cast，直接普通查询
var detailSql = `
    select 
        id,
        purchaseOrderSourceId,
        purchaseOrderSourceDetailId,
        qty, firstupcode
    from \`st.purinrecord.PurInRecords\`
    where mainid = '${billId}'
`;
var detailList = ObjectStore.queryByYonQL(detailSql, 'ustock');

// 结果侧兜底：拿到 Number 后统一转字符串
for (var i = 0; i < detailList.length; i++) {
    detailList[i].id = String(detailList[i].id || '');
    detailList[i].purchaseOrderSourceId = String(detailList[i].purchaseOrderSourceId || '');
}
```

### 9.3 openLinker 返回字符串的强制安全解析

```javascript
var resultString = ObjectStore.openLinker('POST', url, appCode, body);

// ❌ 错误：直接 JSON.parse
// var result = JSON.parse(resultString);

// ✅ 正确：safeJsonParse（强制规范）
var result = safeJsonParse(resultString, {
    longFields: ['id', 'purchaseOrderSourceId', 'purchaseOrderSourceDetailId'],
    lengthThreshold: 16,
    excludeFields: []
});
```

### 9.4 与 Step 2-5 的衔接关系

```
Step 1: 提取 billId
   ↓
Step 2: 主表反查（queryByYonQL）──→ §9.2 防御
   ↓
Step 3: 子表反查（queryByYonQL）──→ §9.2 防御
   ↓
Step 4: 业务调用（openLinker/postman）──→ §9.3 防御
   ↓
Step 5: 参照反查（queryByYonQL）──→ §9.2 防御
   ↓
【新增】Step 7: Long 字段防御（贯穿 Step 2-5 所有 queryByYonQL/API 调用）
```

### 9.5 完整 YonScript 模板（含 Step 7 防御）

```javascript
var AbstractTrigger = require('AbstractTrigger');
class MyTrigger extends AbstractTrigger {
    execute(context, param) {
        // ===== Step 1: 提取 billId（5步反查法）=====
        var billId = extractBillId(context, param);
        if (!billId) {
            throw new Error('【MyTrigger】审批后场景：billId 提取失败');
        }
        // billId 已是 String（平台保护），可直接拼接 SQL
        console.error('【MyTrigger】单据ID:' + billId);

        // ===== Step 2-5: 反查主表/子表/孙表/参照 =====
        var mainSql = `select id, code, transType, orgId
                       from \`cpu-supplymgr.supplystatuschange.SupplyStatusChange\`
                       where id = '${billId}' and dr = 0`;
        var mainList = ObjectStore.queryByYonQL(mainSql, 'cpu-supplymgr');
        
        // ===== 【新增 Step 7.1】queryByYonQL 返回值防御 =====
        for (var i = 0; i < mainList.length; i++) {
            mainList[i].id = (mainList[i].id).toString();  // 保险起见
            mainList[i].transType = (mainList[i].transType).toString();
            mainList[i].orgId = (mainList[i].orgId).toString();
        }
        
        // ===== 业务逻辑（含 openLinker 调用） =====
        var resultString = ObjectStore.openLinker('POST', url, appCode, body);
        
        // ===== 【新增 Step 7.2】openLinker 返回字符串防御（强制） =====
        var result = safeJsonParse(resultString, {
            longFields: ['id', 'purchaseOrderSourceId', 'purchaseOrderSourceDetailId'],
            lengthThreshold: 16
        });
        
        return {};
    }
}
exports({ entryPoint: MyTrigger });
```
