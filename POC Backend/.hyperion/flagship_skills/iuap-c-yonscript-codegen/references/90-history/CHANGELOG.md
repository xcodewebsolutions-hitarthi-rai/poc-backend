## v5.1.8 (2026-07-10) — 既有脚本补丁边界纪律与 NCC 现场封装优先

### 修改
- `references/00-governance/02_V8沙箱安全模式.md`：新增既有脚本补丁边界纪律，要求修改边界前后三行保持原样，禁止在边界行增删注释、改格式或顺手重排；必要注释只能写入本次被修改逻辑内部。
- `references/00-governance/02_V8沙箱安全模式.md`：明确变量声明允许 `var`/`let`，但平台模板壳首行必须原样保持 `let AbstractTrigger = require('AbstractTrigger');` 或 `let AbstractAPIHandler = require('AbstractAPIHandler');`，前后不得新增空格、空行、注释或换行。
- `references/10-common/01_代码框架.md`：补强 Rule/API 模板壳保护，禁止把平台模板首行 `let` 改成 `var`。
- `references/30-scenes/03_三方集成封装.md`：新增 NCC/高级版现场封装优先规则；如现场已提供 `RBSM.APIhs.InvokeNCC` 等统一脚本，业务脚本只传业务报文和 URI，禁止绕过封装重拼 `nccEnv` 或直接调用 `ObjectStore.nccLinker`。
- `references/30-scenes/03_三方集成封装.md`：移除“未使用 let”的残留自检，统一遵循治理层 `var`/`let` 规则。
- `references/00-governance/04_输出契约.md`：自检清单增加补丁边界前后三行不变、三方/NCC现场封装复用检查。
- `references/40-guides/00_整体架构.md`：明确补丁边界纪律归治理层，三方/NCC封装选择归场景层，远程调用通用层只保留基础 API 示例。

### 设计原则
- **边界不变**：小范围补丁不扰动周边上下文，避免平台脚本模板或现场既有代码被无意改写。
- **注释内聚**：注释服务于本次修改逻辑，不外溢到补丁上下文边界。
- **现场封装优先**：NCC token、签名、环境配置优先交给现场统一脚本，业务脚本只负责构造业务报文。
- **渐进式加载**：不把本规则硬塞进 `SKILL.md` 大入口；治理纪律、场景编排、输出自检分别落到对应 reference。

## v5.1.7 (2026-07-08) — 自动事实漂移检测与事实锁定

### 新增
- `references/00-governance/09_最新需求事实锁定门禁.md`：
  - 生成前由 agent 自动抽取最新提示词中的高权重业务事实，并与历史实现事实对比。
  - 最新业务事实与历史事实不一致时自动判定为事实漂移，不依赖用户显式纠偏。
  - 新增自动检测流程、事实锁定表、历史噪音隔离、旧对象关键词排除和输出事实来源要求。

### 修改
- `SKILL.md`：L2 治理层前置新增最新需求事实锁定门禁入口；生成决策树新增事实漂移检测分支；不可违反规则新增“自动抽取最新业务事实并重建事实锁”。
- `references/40-guides/00_整体架构.md`：治理层架构增加 G9 最新需求事实锁定门禁，并补充标准加载链分支。
- `references/00-governance/04_输出契约.md`：输出项新增事实锁报告，命中事实漂移时必须列出当前事实、废弃对象和排除关键词。
- `references/00-governance/08_生成准确性保障.md`：Evidence Gate 增加当前事实锁与废弃对象排除证据，废弃对象按 🔴 禁止使用处理。

### 设计原则
- **自动判断优先**：不能等用户指出“不是 X”；最新提示出现新业务对象就要主动重建事实。
- **历史代码只作模式参考**：旧实现不能反向决定当前实体、子表和字段。
- **交付前拦截**：事实漂移不仅生成前识别，还必须进入输出契约和证据门禁，防止规则成为孤岛。
- **渐进式加载**：仅在多对象、纠偏、复用旧代码等高噪音场景加载，不污染普通单对象生成链。

  - 新增特征字段查询专题，明确特征组外层显式返回、多选档案特征携带原字段、生产优先按需嵌套穿透。

- `references/00-governance/01_技术规范.md`
  - 将“LEFT JOIN 语法”升级为“YonQL 查询形态与 LEFT JOIN 语法”。
  - 固化生产禁 `select *`、优先嵌套查询、DateTime 加引号、where 右值限制、group/order 限制。
- `SKILL.md`
  - 通用能力入口增加嵌套子查询和特征字段。
  - 生成决策树增加参照/子表/多选引用/特征字段的信息确认步骤。
- `references/40-guides/00_整体架构.md`
  - 通用能力层 YonQL 节点补充查询形态、嵌套、特征职责。

### 设计原则
- **嵌套优先**：参照穿透、主子表、多选引用默认走嵌套子查询，JOIN 只用于已验证关联场景。
- **生产最小字段**：禁止默认 `select *`，减少数据传输和字段兼容风险。
- **特征组内聚**：特征字段默认位于特征组对象内，必须先确认特征组和特征编码。
- **渐进式增强**：不新建大而全规范，增量补强现有 YonQL 通用能力和门禁。

  - 强化平台包装返回结构：前端应优先按 `{ code, message, data: {...} }` 中的 `data` 解析业务字段。

  - L1/L5 增加 MDF 前端联动 API 契约的按需加载入口。
- `references/40-guides/00_整体架构.md`
  - 场景层增加 MDF 联动 API 契约节点。

### 设计原则
- **前端不臆造查询能力**：MDF 只负责交互和调用后端，业务对象查询交给 YonScript API。
- **后端返回驱动前端解析**：前端解析必须按后端实际返回样例生成，不再默认 `res.xxx`。
- **前后端联动一体生成**：公有云项目中 MDF 查询依赖后端时，不能只交付前端占位函数。

3. 每个子表 key 必查 `tables.<key>`
4. 每个特征组编码必查 `characterGroups`
5. 每个参照 refUri 必二次查目标实体
6. 写完 SQL 必须实际跑一次
7. 错误处理必须捕获
