# YonScript 字段命名契约（权威单一来源）

> **加载时机**：任何字段取值、YonSQL 拼装、参照/特征组/子表/平行表/业务外键关联取值场景。
> **职责**：先识别元数据字段类型，再决定 YonSQL 或代码写法。
> **约束**：平台执行方法名仍为 `ObjectStore.queryByYonQL`；本文统一称查询语言为 YonSQL。

---

## 一、字段类型识别矩阵

元数据 skill 返回后，必须先确认字段类型。禁止把参照、特征、子表、平行表字段按基本字段处理。

| 字段类型 | 元数据依据 | 默认写法 |
|---|---|---|
| 基本类型 | `attributes[].name`，无 `refUri`，非特征组 | 当前实体直接 `select field` |
| 参照 | `attributes[].refUri` | 外层显式选参照字段，嵌套查询目标字段 |
| 特征组 | 主实体属性指向特征组 | 外层显式选特征组，内部按特征编码查询 |
| 特征基本类型 | `characterGroups` 中的特征编码和类型 | 特征组内部直接选特征编码 |
| 特征参照/多选档案 | 特征项存在档案引用结构或 `refUri` | 携带原特征字段，再嵌套查询档案字段 |
| 子表 | `tables.<key>` | 外层选主实体 `id`，子表字段放内部 `select` |
| 平行表 | 独立 URI/domain + 明确关联键 | 分步查询后在脚本合并；不默认 JOIN |
| 多选引用 | 运行时关联字段 + 实际存储档案字段 | 外层选 `id`，内部先选多选字段再嵌套档案字段 |
| 业务外键关联 | 字段只存目标实体 ID，但无 `refUri`、无主子/特征关系 | 对比源实体和目标实体 `domain` 后自动分流 |

## 二、基础命名规则

| 目标 | 规则 |
|---|---|
| YonSQL 字段 | 只能用 `attributes[].name` 或确认后的子表/特征字段编码 |
| 数据库列 | 禁止使用 `dbColumnName` 拼 YonSQL |
| 参照编码/名称 | 二次确认 `refUri` 目标实体含 `code/name`，再嵌套或分步查询 |
| 特征档案编码/名称 | 确认特征档案引用实体含 `code/name`，再嵌套或分步查询 |
| Boolean 条件 | YonSQL 中用 `1` / `0`，不要用 `true` / `false` |
| 字符串/日期条件 | 必须加单引号并转义 |

`_code` / `_name` 只用于业务对象 JSON、前端展示或三方报文的拉平结果；不要把它们当成当前实体的 YonSQL 字段直接查询。

## 三、YonSQL 写法选择

### 3.1 基本类型

```sql
select id, code, name, status
from `xxx.Main`
where id = 'billId'
```

### 3.2 参照

```sql
select id, orgId, (select id, code, name from orgId) as orgInfo
from `xxx.Main`
where id = 'billId'
```

### 3.3 特征组

```sql
select id, productCharacterDef,
       (select id, wenben, booleanKeyTest from productCharacterDef) as characterInfo
from pc.product.Product
where id = 'billId'
```

### 3.4 子表

```sql
select id, code, (select id, materialId, qty from orderProduct) as orderProducts
from po.order.Order
where id = 'billId'
```

### 3.5 多选引用

```sql
select id,
       (select productMore, (select id, code, name from productMore)
        from productMoreList) as products
from `xxx.Main`
where id = 'billId'
```

### 3.6 平行表

```javascript
// 平行表按独立业务对象处理，分步查，再用关联键合并。
var mainSql = "select id, code from `xxx.Main` where id = " + quoteYonQL(billId);
var extSql = "select mainId, extField from `xxx.MainExt` where mainId = " + quoteYonQL(billId);
```

### 3.7 业务外键关联

```text
字段只存目标单据 ID，元数据没有 refUri / 主子 / 特征关系：
  → 先查询源实体元数据和目标实体元数据。
  → 比较 source._entityInfo.domain 与 target._entityInfo.domain。
  → domain 相同：可 LEFT JOIN，主表不设别名，从表必须设别名，返回扁平结构。
  → domain 不同：先查主子数据并收集外键 ID，再按目标 domain 批量查，最后脚本组装。
```

强约束：业务外键关联不得由模型凭字段名判断是否跨域，必须以元数据 `_entityInfo.domain` 比较结果为准。

## 四、禁止清单

| 场景 | 禁止 |
|---|---|
| 字段不存在 | 凭经验写字段 |
| 参照字段 | 未确认 `refUri` 就写 `code/name` |
| 特征字段 | 未确认特征组和特征编码就拼路径 |
| 子表字段 | 凭经验写子表 key |
| 平行表字段 | 当成主表字段或默认 JOIN |
| 多选引用 | 未确认运行时关联字段和实际存储字段就查询 |
| 业务外键关联 | 当成参照嵌套查询，或跨 domain 强行 JOIN |
| 字段翻译 | 把 `_code` / `_name` 当实体字段直接查 |
| 元数据失败 | 继续凭经验拼 YonSQL |

## 五、生成流程

```text
要写 YonSQL 或字段访问代码
  → 判断 uri/domain/字段/条件是否充分且可追溯
  → 不充分则调用 iuap-c-metadata-info
  → 确认字段类型：基本类型/参照/特征/子表/平行表/多选引用/业务外键关联
  → 按字段类型选择写法
  → 输出元数据消费清单和 Evidence Gate
  → 生成代码
```
