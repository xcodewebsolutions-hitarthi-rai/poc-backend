## API 脚本（前端 invokeFunction 调用）

### 基础模板

```javascript
let AbstractAPIHandler = require('AbstractAPIHandler');
class MyAPIHandler extends AbstractAPIHandler {
  execute(request) {
    // 【规范2】日志格式
    console.error('【MyAPIHandler】入参 request:' + JSON.stringify(request));

    // 1. 获取参数
    var param = request.xxx;

    // 2. 业务逻辑...

    // 3. 返回结果
    return { success: true };
  }
}
exports({ entryPoint: MyAPIHandler });
```

### 模板壳保护（强约束）

当生成 API 脚本时，以下模板壳视为**不可变区域**：

```javascript
let AbstractAPIHandler = require('AbstractAPIHandler');
class MyAPIHandler extends AbstractAPIHandler {
  execute(request) {
    return {};
  }
}
exports({ entryPoint: MyAPIHandler });
```

强约束：

- 必须保留 `require → class → execute → return → exports` 的首尾结构。
- API 脚本前三行、后三行不得随意增删、改写或插入空行；首行必须保持平台模板 `let AbstractAPIHandler = require('AbstractAPIHandler');`。
- Rule 脚本前三行、后三行不得随意增删、改写或插入空行；首行必须保持平台模板 `let AbstractTrigger = require('AbstractTrigger');`。
- 模板壳首行前后连空格、空行、注释、换行都不能增删；不得把平台模板首行的 `let` 改成 `var`。
- 业务变量、注释、工具函数全部放进 `execute` 方法体内部；不要在模板外或类方法区新增辅助方法。
- 常量配置默认采用“哪用写哪”的方式，避免为调试方便性引入额外配置层。
- 如果确有必要集中常量，必须确认不会影响在 BIP 后端函数设计器中的定位效率。
- API 查询脚本涉及 YonSQL、DateTime、生产日志、前端返回结构时，加载 `14_API脚本查询与日志模式.md`。

### 注释要求（强约束）

- 生成代码时必须带简明注释。
- 注释优先说明：当前查询目的、当前业务步骤、关键约束。
- 禁止写“变量赋值”“循环开始”这类无信息密度注释。

### 完整示例（含 API 调用）

```javascript
let AbstractAPIHandler = require('AbstractAPIHandler');
class MyAPIHandler extends AbstractAPIHandler {
  execute(request) {
    // 【规范2】日志格式
    console.error('【MyAPIHandler】入参 request:' + JSON.stringify(request));

    // 1. 获取参数
    var customerCode = request.customerCode;

    // 2. 调用BIP客户档案API（URL/入参必须先由 iuap-c-openapi-integration 确认）
    var env = ObjectStore.env();
    var url = env.url + '/iuap-api-gateway/yonbip/digitalModel/customer/detail?id=' + encodeURIComponent(customerCode);
    var resultString = ObjectStore.openLinker('GET', url, 'app_code', null);
    var result = safeJsonParse(resultString, { longFields: [], lengthThreshold: 16 });

    // 3. 返回结果
    if (result && result.code === '200') {
      return { success: true, data: result.data };
    }
    return { success: false, message: result.message || '查询失败' };
  }
}
exports({ entryPoint: MyAPIHandler });
```

## Rule 脚本（MDD 规则链 / YPD 扩展点绑定）

### 基础模板

```javascript
let AbstractTrigger = require('AbstractTrigger');
class MyTrigger extends AbstractTrigger {
  execute(context, param) {
    // 【规范2】日志格式
    console.error('【MyTrigger】入参 param:' + JSON.stringify(param));

    // 业务逻辑...

    return {};
  }
}
exports({ entryPoint: MyTrigger });
```

### MDD 规则链完整示例

```javascript
let AbstractTrigger = require('AbstractTrigger');
class MyTrigger extends AbstractTrigger {
  execute(context, param) {
    // 【规范2】日志格式
    console.error('【MyTrigger】入参 param:' + JSON.stringify(param));

    // 1. 获取单据数据（MDD 规则链使用 param.data）
    var billData = param.data[0];
    var billId = billData.id;
    console.error('【MyTrigger】单据ID:' + billId);

    // 2. YonSQL 查询（【规范1】URI 含 '-' 用反引号）
    var sql = "select code, name from `xxx-yyy.Entity` where id = '" + billId + "'";
    console.error('【MyTrigger】查询SQL:' + sql);
    var result = ObjectStore.queryByYonQL(sql, 'domainKey');
    console.error('【MyTrigger】查询结果:' + JSON.stringify(result));

    // 3. 业务逻辑...

    return {};
  }
}
exports({ entryPoint: MyTrigger });
```

### YPD 扩展点完整示例

```javascript
let AbstractTrigger = require('AbstractTrigger');
class MyTrigger extends AbstractTrigger {
  execute(context, param) {
    // 【规范2】日志格式
    console.error('【MyTrigger】入参 param:' + JSON.stringify(param));

    // 1. 获取单据数据（YPD 扩展点使用 param.billDOs）
    var bills = param.billDOs || (param.billDO ? [param.billDO] : []);
    var billData = bills[0];
    var billId = billData.id;

    // 2. 获取操作类型
    var action = context.action;
    console.error('【MyTrigger】操作类型:' + action);

    // 3. 根据操作类型执行不同逻辑
    if (action === 'audit') {
      // 审核后处理...
    }

    return {};
  }
}
exports({ entryPoint: MyTrigger });
```

## 脚本编码命名规范

| 脚本类型 | 编码格式 | 示例 |
|---------|---------|------|
| API 脚本 | `GTxxx.Module.function` | `GT3734AT5.pub.queryCustomer` |
| Rule 脚本 | `GTxxx.Module.ruleName` | `GT3734AT5.rule.vendorApprove` |

> 脚本编码用于前端调用 `invokeFunction('GTxxx.Module.function', params, callback)`，详见 [../40-guides/02_后端脚本绑定指南.md](../40-guides/02_后端脚本绑定指南.md)。

## 本地脚本文件命名规范

本地交付文件名必须表达业务含义，末尾只标识脚本类型。

| 脚本类型 | 文件名格式 | 示例 |
|---------|------------|------|
| API / 开放函数 | `{业务对象}{动作}{Handler}.js` | `supplyCatalogManufacturerQueryHandler.js` |
| Rule / 规则函数 | `{业务对象}{动作}{Rule}.js` | `purchaseContractManufacturerSubmitRule.js` |

强约束：

- 文件名主体必须有业务语义，不能只写 `rule.js` / `handler.js`。
- 文件名禁止带项目编码、微服务名、工程名，例如 `c_scm_kk_liuzu`、`service`、`bootstrap`。
- `Rule` / `Handler` 只作为末尾类型标识，不替代业务命名。
- 平台绑定编码和本地文件名分离：平台编码按函数设计器实际编码填写，本地文件名用于交付识别。
